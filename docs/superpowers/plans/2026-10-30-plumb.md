# Plumb Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a client-side BepInEx mod that scales every material's `_RippleDistance` so building
pieces look straight (strength 0), vanilla (1) or warped more (up to 3).

**Architecture:** a pure model (`Core/Model/`) does the arithmetic and keeps the vanilla value
for each material base name. `Ripple` scans the loaded materials when a world loads and writes
`vanilla × strength` to the shared materials. This happens once per world load and once per
setting change, never per piece or per frame. Patches cover world load, the console command and
the compare hotkey.

**Tech Stack:** C# net472, BepInEx 5, Harmony, BepInEx.AssemblyPublicizer.MSBuild, xunit on
net8.0 for the model. No Jotunn.

**Spec:** `PLAN.md` (repo root). Read it first: §1 has the decompiled-code findings and §5 has
the rig checks.

## Review Focus

1. **Runtime copies of a material compounding the scale.** The ghost uses `new Material(src)`
   and `renderer.material` creates `"X (Instance)"`. Either kind of copy already holds the scaled
   value. If a later scan records that as "vanilla", applying again compounds the scale. Expected:
   copies resolve to the vanilla value of their base name. Test: `VanillaTable` tests in Task 2.
2. **Leaving and re-entering a world, or rescanning, at strength ≠ 1.** Expected: the values
   are the same as after the first load. Test: `VanillaTable` keeps the first-seen value (Task 2),
   and the rig check in Task 3, step 7.
3. **Typing in chat or the console while `CompareKey` is bound to a letter.** Expected: compare
   doesn't toggle. Test: rig check in Task 3, step 7.
4. **Command arguments like `0,5`, `-1`, `NaN` or `abc`.** Expected: usage is printed and nothing
   changes. Test: `TryParseStrength` tests in Task 2.
5. **Strength changed in the cfg or a config manager in the main menu, before any world.**
   Expected: no exception. Values are applied at the next world load. Test: rig check in Task 3,
   step 7.

### Task 3: Ripple, config, patches and console, verified on the rig

**Files:**
- Create: `src/Plumb/PluginConfig.cs`, `src/Plumb/Ripple.cs`, `src/Plumb/Patches/ZNetScenePatch.cs`,
  `src/Plumb/Patches/ConsolePatch.cs`, `src/Plumb/Patches/ComparePatch.cs`
- Modify: `src/Plumb/Plugin.cs` (bind the config and add the Badgers warning)

**Interfaces:**
- Consumes: `WarpModel.Target`, `WarpModel.TryParseStrength`, `VanillaTable.Resolve` and
  `VanillaTable.Count` from Task 2.
- Produces:
  - `PluginConfig.Strength` (`ConfigEntry<float>`) and `PluginConfig.CompareKey`
    (`ConfigEntry<KeyboardShortcut>`).
  - `static class Ripple`, with:
    - `void Scan()` and `void Apply()`
    - `bool Compare { get; set; }`, where setting it calls `Apply()`
    - `int MaterialCount`
    - `string Describe()`

- [ ] **Step 1: Write `PluginConfig`.**
  - `Strength`: section `General`, default `0f`, `AcceptableValueRange<float>(0f, WarpModel.MaxStrength)`.
    Description: "How much building pieces warp. 0 = perfectly straight, 1 = vanilla, up to 3 =
    more warped than vanilla."
  - `CompareKey`: `KeyboardShortcut.Empty`. Description: "Toggle between vanilla warp and your
    Strength, to compare. Not saved."
  - `Strength.SettingChanged` calls `Ripple.Apply()`.
- [ ] **Step 2: Write `Ripple`.**
  - It holds a `static readonly ID = Shader.PropertyToID("_RippleDistance")`, a `VanillaTable`
    and a `HashSet<Material>`.
  - `Scan()` adds each `Resources.FindObjectsOfTypeAll<Material>()` where `HasProperty(ID)` is
    true, calling `table.Resolve(m.name, m.GetFloat(ID))` for each.
  - `Apply()` removes destroyed materials (`m == null`), then calls
    `m.SetFloat(ID, WarpModel.Target(table.Resolve(m.name, 0f), Strength.Value, Compare))`.
    `Resolve` returns the recorded vanilla value here, because every material in the set was
    recorded during `Scan`.
  - On the first scan, log the material count and the distinct vanilla values. This answers
    PLAN.md §5.
- [ ] **Step 3: Write the patches.**
  - `ZNetScenePatch`: Harmony `Postfix` on `ZNetScene.Awake` that calls `Ripple.Scan(); Ripple.Apply();`.
  - `ConsolePatch`: register `new Terminal.ConsoleCommand("plumb", ...)` the same way as
    `Earshot/src/Earshot/Core/EarshotConsole.cs` and in the same hook. With no argument, print
    `Ripple.Describe()`. With a valid argument, set `PluginConfig.Strength.Value` and print
    `Describe()`. Otherwise print `plumb [0-3]   0 = straight, 1 = vanilla`.
  - `ComparePatch`: `Postfix` on `Player.Update`, only for `Player.m_localPlayer`. If
    `CompareKey.Value.IsDown()` is true and neither `Console.IsVisible()` nor
    `Chat.instance != null && Chat.instance.HasFocus()` is true, flip `Ripple.Compare`.
  - Verify each target's name and signature in `decomp/` before writing the patch.
- [ ] **Step 4: Add the Badgers warning to `Plugin.cs`.**
  - In `Start()`, so that all plugins are loaded, check
    `BepInEx.Bootstrap.Chainloader.PluginInfos.Values` for a plugin whose GUID or name contains
    `StraightStructures` (case-insensitive).
  - Log this warning: "Badgers Straight Structures is also installed; both change the same
    setting and the last one to run wins. Remove one."

- [ ] **Step 6: Deploy.**
